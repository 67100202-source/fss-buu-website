# คู่มือติดตั้งฐานข้อมูล Supabase (ทำตามทีละขั้น)

> ใช้เวลาประมาณ **15–20 นาที** ทำครั้งเดียว แล้วเว็บทั้งเว็บจะดึงข้อมูลจากฐานข้อมูลจริง
> ไม่ต้องแก้โค้ด JavaScript เลยในขั้นตอนนี้

> ✅ **ไฟล์ SQL ที่ต้องใช้ได้เตรียมไว้ให้แล้ว** (แปลงจากไฟล์ `fss_buu_database.sql` ของคุณเป็น PostgreSQL เรียบร้อย)
> - `supabase/schema.sql` — โครงสร้างตาราง 19 ตาราง + RLS + สิทธิ์ Admin
> - `supabase/seed.sql` — ข้อมูลจริงทั้งหมด (หลักสูตร 5, อาจารย์ 21, บุคลากร 9, ข่าว 10, ทุน 3, ผลงาน 4, ปฏิทิน 4, คลังสื่อ 3)
> - 📖 `docs/database_schema.md` — เอกสารอธิบายที่มาของข้อมูลแต่ละชุด (อ้างอิงแหล่ง URL จากเว็บคณะ)

---

## ขั้นตอนที่ 1 : สร้างบัญชีและโปรเจกต์

1. เปิดเว็บ **https://supabase.com** แล้วกด **Start your project**
2. กด **Continue with GitHub** (หรือ Google) เพื่อสมัคร / เข้าสู่ระบบ
3. สร้างโปรเจกต์ใหม่:
   - **Organization** — เลือกองค์กรส่วนตัว (personal) ก็ได้
   - **Name** — ตั้งชื่อ เช่น `fss-buu`
   - **Database Password** — **ตั้งรหัสผ่านแล้วบันทึกไว้** (ต้องใช้ตอนล็อกอิน SQL Editor)
   - **Region** — เลือก `Bangkok` หรือ `Singapore` (ใกล้ที่สุด)
4. กด **Create new project**
5. รอประมาณ 1–2 นาทีให้ระบบสร้างฐานข้อมูลเสร็จ

> ⚠️ **สำคัญ:** รหัสผ่านฐานข้อมูล (Database Password) ที่ตั้งในขั้นนี้ **ไม่เหมือนกัน** กับ anon key ที่จะใช้ในโค้ด
> รหัสผ่านนี้ใช้เฉพาะตอนจะเข้า SQL Editor เท่านั้น ห้ามใส่ในโค้ดเว็บเด็ดขาด

> 💡 **เรื่องรหัสผ่าน Admin ในตาราง `admin_users`**
> ในไฟล์ SQL ของคุณ ค่า `password_hash` เป็นค่าจำลอง (`hashed_password_demo_2569`) ไม่ใช่ hash จริง
> ระบบล็อกอินของเว็บเราใช้ **Supabase Auth** ( ปลอดภัยกว่า และไม่ต้องเก็บ hash ในตาราง )
> ตาราง `admin_users` ยังคงไว้เพื่อเก็บข้อมูลโปรไฟล์ ( ชื่อ-นามสกุล, ตำแหน่ง, อีเมล ) ของผู้ดูแล

## ขั้นตอนที่ 2 : สร้างตารางทั้งหมด

1. ในหน้า Dashboard ของโปรเจกต์ กดเมนูด้านซ้าย **SQL Editor** → กด **New query**
2. เปิดไฟล์ `supabase/schema.sql` ในโปรเจกต์นี้ → **คัดลอกทั้งไฟล์**
3. วางในช่อง SQL Editor
4. กด **Run** (ปุ่มเขียว หรือ Ctrl+Enter)
5. รอสักครู่ → ต้องเห็นข้อความ `✅ สร้างโครงสร้างฐานข้อมูลเรียบร้อย`

> **ถ้าเจอ error:** อ่านข้อความแดงด้านล่าง แล้วแก้บรรทัดนั้นแล้วรันใหม่
> ไฟล์ schema.sql ใช้ `if not exists` ทั้งหมด จึง**รันซ้ำได้ปลอดภัย** ไม่ต้องกลัวข้อมูลหาย

### ถ้า error ตรงส่วนที่ 6 (Storage)

บางโปรเจกต์อาจรันส่วน Storage ไม่ผ่านเพราะต้องเป็นเจ้าของโปรเจกต์
ให้รันแค่ส่วนนี้แยก (ตัดจาก `insert into storage.buckets` ถึงท้ายส่วนที่ 6) ใน SQL Editor ใหม่

## ขั้นตอนที่ 3 : เติมข้อมูลตัวอย่างลงฐานข้อมูล

1. SQL Editor → **New query** (อีกครั้ง)
2. คัดลอกไฟล์ `supabase/seed.sql` ทั้งไฟล์ มาวาง
3. กด **Run**
4. ต้องเห็น `✅ เติมข้อมูลตัวอย่างเรียบร้อย`

> หน้าเว็บจะดึงข้อมูลจากตารางเหล่านี้แทนข้อมูลตัวอย่างใน `js/data.js`
> (ถ้าอยากให้หน้าเว็บแสดงข้อมูลตัวอย่างในไฟล์เหมือนเดิม ให้ข้ามขั้นตอนนี้ได้ แต่แนะนำให้รัน)

## ขั้นตอนที่ 4 : สร้างบัญชี Admin

1. เมนูด้านซ้าย → **Authentication** → **Users** → กด **Add user** → **Create a new user**
2. กรอก:
   - **Email** — ใช้อีเมลของผู้ดูแลจริงจากตาราง `admin_users` เช่น `attaporns@go.buu.ac.th`
   - **Password** — ตั้งรหัสผ่านที่แน่นอน (อย่างน้อย 8 ตัว)
   - ✅ เช็ค **Auto Confirm User**
3. กด **Create user**

> บัญชีนี้จะใช้ล็อกอินเข้าหน้า Admin ภายหลัง
> **ห้ามใส่รหัสผ่านนี้ในโค้ดเว็บ** — ให้ผู้ใช้พิมพ์เองในหน้า Login เท่านั้น
>
> 💡 ผู้ดูแลในไฟล์ฐานข้อมูลของคุณมี 2 บัญชี
> - `attaporns@go.buu.ac.th` (นายอัฐพร โสวัตร์) — superadmin
> - `phanpaporn@go.buu.ac.th` (นางพรรณปพร เผ่าจินดา) — editor
> แนะนำให้สร้างทั้งสองบัญชี เพื่อทดลองสิทธิ์ระดับต่างกัน

## ขั้นตอนที่ 5 : ให้สิทธิ์ Admin

1. SQL Editor → **New query**
2. รันคำสั่งนี้ (เปลี่ยนอีเมลให้ตรงกับที่ตั้งในขั้นตอนที่ 4):

```sql
update public.profiles
set role = 'admin'
where email = 'attaporns@go.buu.ac.th';
```

3. ต้องได้ผลลัพธ์ `UPDATE 1` (แปลว่าอัปเดตสำเร็จ 1 แถว)

> 💡 ตาราง `profiles` จะสร้างแถวให้อัตโนมัติเมื่อมีผู้สมัครสมาชิกใหม่
> (ผู้สมัครใหม่จะได้ role = 'user' ซึ่งเข้าหน้า Admin ไม่ได้ แต่ใช้ระบบสมาชิกนิสิตได้)
>
> 💡 ถ้าอัปเดตแล้วได้ `UPDATE 0` แปลว่ายังไม่มีแถวใน `profiles`
> ให้รอสักครู่แล้วรันซ้ำ หรือรันคำสั่งนี้แทน:
> ```sql
> insert into public.profiles (id, email, full_name, role)
> select id, email, email, 'admin' from auth.users where email = 'attaporns@go.buu.ac.th'
> on conflict (id) do update set role = 'admin';
> ```

## ขั้นตอนที่ 6 : เอา URL และ anon key มาใส่ในโค้ด

1. เมนูด้านซ้าย → **Project Settings** (ไอคอนเฟือง) → **API**
2. คัดลอก 2 ค่านี้:
   - **Project URL** → เช่น `https://abcdefghijklm.supabase.co`
   - **anon public** key → ขึ้นต้นด้วย `eyJ...`
3. เปิดไฟล์ **`js/supabase-config.js`** แล้ววาง:

```js
const SUPABASE_URL = "https://abcdefghijklm.supabase.co";   // ← ของคุณ
const SUPABASE_ANON_KEY = "eyJhbGciOiJIUzI1NiIsInR5cCI6...";  // ← ของคุณ
```

> 🔐 **anon key ใส่ในโค้ดได้เลย** เพราะออกแบบมาให้สาธารณะอยู่แล้ว
> ความปลอดภัยมาจากกฎ RLS ที่เราตั้งไว้ในขั้นตอนที่ 2
>
> 🚫 **ห้ามใส่ `service_role` key เด็ดขาด** — คีย์นั้นข้าม RLS ได้ ถ้าหลุดออกไปผู้อื่นจะแก้ข้อมูลทั้งเว็บได้

## ขั้นตอนที่ 7 : ทดสอบ

เปิดเว็บไซต์ (ถ้ายังไม่มี server ให้รัน `python -m http.server 8899` ในโฟลเดอร์โปรเจกต์)

ตรวจสอบว่า:
1. แถบเตือน ⚠️ "ข้อมูลตัวอย่าง" **ยังอยู่** — เป็นเรื่องปกติ (เดี๋ยวค่อยลบตอนเขียนเสร็จจริง)
2. เปิด **Console** ของเบราว์เซอร์ (กด F12) ดูว่าไม่มี error
3. ถ้าอยากตรวจว่าเชื่อมต่อสำเร็จ ให้พิมพ์ใน Console:

```js
getSupabase() !== null   // ต้องได้ true
```

## การอัปเดตข้อมูลในภายหลัง (ยิ่งยวดมาก)

- **ข้อมูลที่เพิ่มใหม่** → ใช้หน้า Admin ที่เราจะสร้างต่อ (ยังไม่ได้ทำ)
- **แก้ไขข้อมูลเดิม** → เข้า **Table Editor** ใน Supabase Dashboard แก้ได้เลย
- **ลบข้อมูล** → Table Editor → กดไอคอนถังขยะ

> ทุกครั้งที่แก้ข้อมูล **อย่าลืมกด Save** และเครื่องหมาย ✓ สีเขียว

## โครงสร้างตารางทั้งหมด (19 ตาราง)

### ตารางหลัก (จากฐานข้อมูลจริงของคณะ — `fss_buu_database.sql`)

| ตาราง | ใช้ทำอะไร | จำนวนข้อมูล |
|---|---|---|
| `programs` | หลักสูตร 5 สาขา (ปริญญาตรี/โท/เอก) | 5 |
| `instructors` | ทำเนียบอาจารย์ 21 คน | 21 |
| `staff_members` | บุคลากรสำนักงานคณบดี | 9 |
| `news_articles` | ข่าว + ข่าวกีฬา (มีธง `status` = draft/published) | 10 |
| `scholarships` | ประกาศทุน + เอกสารแนบ | 3 |
| `achievements` | ผลงานนิสิตและศิษย์เก่า | 4 |
| `calendar_events` | ปฏิทินการศึกษา/กิจกรรม | 4 |
| `media_gallery` | คลังภาพ + วิดีโอ YouTube | 3 |
| `form_submissions` | ข้อความจากแบบฟอร์ม (ติดต่อ/สมัครกิจกรรม) | 2 |
| `admin_users` | ข้อมูลโปรไฟล์ผู้ดูแลระบบ | 2 |

### ตารางที่เพิ่มเติม (หน้าเว็บต้องใช้)

| ตาราง | ใช้ทำอะไร |
|---|---|
| `schedules` | (ถูกลบออกแล้ว - ไม่ใช้งานตารางเรียนรายชั้นปีอีกต่อไป) |
| `match_results` | ผลการแข่งขัน |
| `match_fixtures` | ตารางการแข่งขันที่กำลังจะมาถึง |
| `athletes` | นักกีฬาคณะ |
| `banners` | สไลด์หน้าแรก |
| `quick_links` | ทางลัดตามกลุ่มผู้ใช้ |
| `services` | ตารางไอคอนทางลัด |
| `partners` | หน่วยงานที่เกี่ยวข้อง |
| `contact_info` | ข้อมูลติดต่อใน footer |
| `profiles` | ผู้ใช้ + สิทธิ์ Admin (ผูกกับ Supabase Auth) |

### กฎสิทธิ์ (RLS) ที่ตั้งไว้

| กลุ่ม | ใครอ่านได้ | ใครเขียนได้ |
|---|---|---|
| ข่าว / ทุน / ปฏิทิน / คลังสื่อ | ทุกคน (เฉพาะ `status='published'`) | Admin เท่านั้น |
| หลักสูตร / อาจารย์ / บุคลากร / ผลงาน | ทุกคน | Admin เท่านั้น |
| `form_submissions` | ทุกคน**ส่งได้** แต่**อ่านไม่ได้** | Admin เท่านั้น |
| `profiles` | ดูของตัวเอง / Admin ดูได้ทั้งหมด | Admin เท่านั้น |

## แก้ปัญหา

| ปัญหา | วิธีแก้ |
|---|---|
| `getSupabase()` คืน `null` | ยังไม่ได้ใส่คีย์ หรือใส่ผิดช่อง — เช็ค `js/supabase-config.js` |
| หน้าเว็บข้อมูลหายไปหมด | ตารางใน DB ว่างอยู่ → รัน `seed.sql` |
| ขึ้น `relation "news_articles" does not exist` | ยังไม่ได้รัน `schema.sql` |
| ขึ้น error เรื่อง RLS / permission | ตรวจว่ารัน `schema.sql` ครบทั้งไฟล์ (โดยเฉพาะส่วนสร้าง policy) |
| ข้อมูลซ้ำเมื่อรัน `seed.sql` ซ้ำ | ไฟล์ seed.sql มีคำสั่ง `truncate` ล้างข้อมูลเดิมก่อนอยู่แล้ว ปลอดภัย |
| SQL Editor ขอรหัสผ่าน | ใช้รหัสผ่านฐานข้อมูล (Database Password) ที่ตั้งในขั้นตอนที่ 1 |
| อยากกลับไปใช้ข้อมูลตัวอย่างในไฟล์ | เปลี่ยน `SUPABASE_URL` กลับเป็นค่าเดิม หรือลบคีย์ออก |
